# OPAQUE — Working State

## Status

**Provisional control document.** This document records the current working state of OPAQUE specification work. It does not itself ratify unconfirmed requirements, architecture, or implementation.

## 1. Identity

**System:** OPAQUE  
**Type:** Meta Scheme of Work / meta-level project-control system  
**Parent:** None / Not Applicable  
**Scope:** Project control from practical execution and time management through theoretical specification and system governance  
**Version:** 1.0.0 working baseline

OPAQUE exists to make the EverWorlds project controllable under complexity, incompleteness, uncertainty, human–AI interaction problems, execution disruption, and change.

## 2. Why OPAQUE Exists

OPAQUE exists because an ambitious project can fail without a reliable control system even when its underlying ideas are strong.

The system must therefore help prevent or compensate for:

- disorder and loss of project structure;
- uncontrolled decomposition;
- missing prerequisites;
- hidden dependencies;
- unclear authority;
- accidental promotion of conversation into project truth;
- AI over-compliance or uncritical interpretation;
- misunderstanding;
- cognitive overload;
- ineffective explanation;
- loss of progress visibility;
- emotional disruption of project decisions;
- burnout and loss of execution continuity;
- incomplete specifications;
- uncontrolled change;
- loss of traceability;
- implementation diverging from intended requirements;
- failure to recognize when the current working method itself has become defective.

These are problem domains. Their final mechanisms remain to be specified.

## 3. Governing Spine

The working control spine is:

**EverWorlds → OPAQUE Specification Framework → OPAQUE Specification → OPAQUE → Scheme of Work → Execution → Observation/Feedback → OPAQUE**

The specification process itself must remain subject to control:

**Current State → Objective → Constraints → Independent Assessment → Action → Verification → Reassessment**

A continuation instruction such as “next” means continue the justified project process. It does not authorize uncontrolled local decomposition.

## 4. OPAQUE Boundary

EverWorlds is the substantive project.

OPAQUE governs the conditions under which relevant project information, decisions, work, AI activity, changes, and execution remain controlled.

The Scheme of Work is the operational organization of work.

Execution is actual performance of work.

OPAQUE is not the substantive EverWorlds product, not the Scheme of Work itself, and not a replacement for legitimate human authority.

## 5. AI Operating Boundary

OPAQUE requires strong reasoning agency from the AI while preserving project authority boundaries.

**AI reasoning agency ≠ AI project authority.**

The AI should independently:

- detect missing prerequisites;
- detect contradictions and ambiguity;
- challenge weak premises;
- identify process drift;
- determine when research is required;
- determine when a branch has saturated;
- identify when an action is premature;
- maintain milestone and completion conditions;
- propose corrections;
- preserve continuity.

The AI must not silently convert its own inference, preference, interpretation, or conversational momentum into authoritative project state.

## 6. Human–AI Interaction Control

OPAQUE must account for the fact that the human-facing representation of reasoning need not have the same complexity as the internal reasoning required to maintain project integrity.

Required distinction:

**Internal reasoning complexity ≠ required user-facing complexity.**

The system should be capable of producing, when appropriate:

### Simple operational explanation

- where we are;
- what we are doing;
- why it matters;
- what has already been established;
- what remains;
- what completes the current milestone;
- what happens next.

### Technical representation

Detailed formal reasoning, dependencies, uncertainty, alternatives, validation, and future implications.

The user must not be required to consume the full technical representation merely to understand the current practical situation.

## 7. Metacognitive Control

Every substantive OPAQUE action should begin with examination of the current epistemic, procedural, interactional, and project state.

The working loop is:

**Audit Current State → Detect Change/Drift → Re-establish Understanding → Perform Action → Audit Result**

The audit must examine at least:

1. project-state changes;
2. process/workflow changes;
3. interaction and communication changes;
4. efficiency and cognitive-load changes;
5. epistemic status changes.

Detection does not itself authorize modification.

**Detection ≠ Modification.**

Optimization proposals do not become rules without appropriate authorization.

## 8. Convergence Requirement

OPAQUE specification work must have explicit milestones and completion conditions.

The process must prevent:

**Local examination → endless decomposition → loss of global objective → cognitive overload.**

Instead:

**Explore → Determine Relevance → Extract → Compress → Check Sufficiency → Close → Advance**

A branch should continue only when unresolved material is necessary to satisfy the current milestone.

Maximum practical identification does not mean maximum possible decomposition.

## 19. Corrective Control

The specification process must maintain visible:

**Current Milestone → Current Objective → Established Findings → Remaining Material → Reason for Next Action → Completion Condition → Next Milestone**

The AI should not require the user to maintain this structure through repeated continuation prompts.

## 20. Interruption and Recovery

Interruption is not treated as process failure.

If the user asks to stop, summarize, inspect, audit, or determine progress, the process must be able to reconstruct its state and continue without destroying the reasoning chain.

The system must preserve the distinction between:

- project state;
- specification-process state;
- human interaction state;
- AI reasoning state.

A temporary disruption in one does not automatically redefine the others.
