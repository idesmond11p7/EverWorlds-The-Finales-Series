# EverWorlds Scheme of Work

## Status

**Living production framework**

This is a project productivity and production framework, not a school-style teaching document.

Its purpose is to move EverWorlds toward completion while reducing burnout, disorder, inconsistency, continuity drift, uncontrolled scope, repeated work, and AI-generated compounding errors.

GitHub is the authoritative documentation home.

---

## 1. Work Model

**Project → Phase → Task → Verification → Review → Next Action**

### Project
The larger EverWorlds objective.

### Phase
A bounded area of work with a defined purpose and completion condition.

### Task
A concrete unit of work that produces an identifiable result.

### Verification
Check the result against the relevant source of truth before dependent work continues.

### Review
Evaluate correctness, continuity, quality, blockers, and remaining work.

### Next Action
The smallest meaningful action required to continue safely.

---

## 2. Work Areas

The framework accommodates:

1. Research
2. Writing / Story / Narrative / Episodes
3. Visual development
4. Production / Implementation
5. Testing / Verification
6. Documentation
7. Marketing / Presentation
8. Other work that is deliberately added later

---

## 3. Work States

Every meaningful work item should have an explicit state:

- **Confirmed** — supported by an authoritative record.
- **Working Assumption** — currently used but not permanently established.
- **Proposal** — suggested direction awaiting acceptance.
- **Open Question** — unresolved and requiring research, testing, or judgment.
- **Active** — currently being worked.
- **Revision Required** — exists but fails a quality/continuity/verification condition.
- **Blocked** — cannot safely proceed because a dependency is unresolved.
- **Paused** — intentionally stopped.
- **Cancelled / Retired** — no longer active.
- **Complete** — completion condition has been satisfied and verified.

Unconfirmed ideas must not silently become requirements.

---

## 4. Authority and Conflict Control

When sources disagree, do not silently choose whichever source is convenient.

Use the relevant authoritative record.

Current working precedence:

1. Explicit locked decisions and requirements
2. Authoritative narrative/canon locks
3. Project Bible / controlled terminology
4. Verified research and implementation evidence
5. Working plans
6. Proposals / raw ideation

A lower-level plan cannot silently override a higher-level lock.

If two authoritative sources genuinely conflict:

**STOP.**

Resolve the conflict before building dependent work.

---

## 5. Autonomous Work-Control Rule

AI agents are production participants.

Before advancing work, the agent should:

1. identify the current phase;
2. inspect the relevant source of truth;
3. identify locked decisions;
4. identify unresolved dependencies;
5. test whether the requested next step is actually safe;
6. perform the task;
7. verify the result;
8. record important changes;
9. state the next concrete action.

### Mandatory STOP conditions

Stop instead of continuing when:

- a hard lock would be violated;
- authoritative sources conflict;
- the current approach is demonstrably failing;
- speculation has become necessary;
- continuation would compound a known error;
- required information has not been verified.

The user's “next” or “continue” is not permission to bypass a known blocker.

---

## 6. Daily Session Cycle

### Opening

- identify current phase;
- read relevant state;
- inspect carried work;
- verify first action;
- note new constraints.

### Active Work

Work on the smallest meaningful task that advances the phase.

Do not open unrelated conceptual branches unless they are required for the current task.

### Verification

Check:

- source-of-truth alignment;
- continuity;
- terminology;
- dependencies;
- invented assumptions;
- actual task completion.

### Closing

Record:

- completed work;
- important changes;
- carried work;
- blockers;
- first action for next session;
- current status.

---

## 7. Work Log Discipline

Where available, record:

1. Date
2. Start time
3. End time
4. Total time
5. Phase
6. Task
7. Completed work
8. Carried work
9. Blockers
10. Next session's first action
11. Status

Never invent missing times.

When deliberately stopping:

**Paused for today**

and record the exact resumption point.

---

## 8. Weekly Review

Weekly review checks:

### Progress
- meaningful work completed;
- phases advanced;
- deliverables produced.

### Continuity
- decisions preserved;
- contradictions;
- documentation drift;
- narrative/canon drift.

### Efficiency
- repeated work;
- failed approaches;
- unnecessary process;
- AI failure patterns.

### Blockers
- unresolved dependencies;
- research gaps;
- technical failures;
- decisions requiring user judgment.

### Sustainability
- time invested;
- workload;
- burnout risk;
- whether the process itself has become overhead.

### Next priorities

Keep the next week's priorities limited to meaningful work. Do not create task volume merely to look organized.

# 9. Narrative Production Workstream

The novel is a real production workstream inside EverWorlds.

Workflow:

**Narrative Canon → Chapter Plan → Research / Verification → Scene Construction → Draft → Continuity Check → Prose Review → Release**

### Canon Check

Before drafting, verify:

- character identity;
- character knowledge;
- chronology;
- setting;
- world rules;
- established events;
- exclusions;
- unresolved information.

### Chapter Plan

Every chapter needs:

- starting state;
- narrative function;
- required discoveries;
- major scenes;
- character movement;
- information revealed;
- information deliberately withheld;
- ending state;
- next-chapter handoff.

### Research

Research only when real-world knowledge materially affects plausibility.

Relevant examples:

- period technology;
- Japanese transit;
- geography;
- school administration;
- educational materials;
- psychology;
- human behaviour;
- period culture.

### Drafting

Do not force one universal prose style onto the novel.

Scene-appropriate modes may include:

- grounded everyday prose;
- conversational dialogue;
- comedy;
- introspection;
- lyrical description;
- action;
- surreal experience;
- cinematic supernatural description;
- quiet emotional scenes;
- horror when explicitly intended.

Modes may switch organically within a chapter.

### Continuity Review

Verify:

- first-person knowledge boundaries;
- chronology;
- names;
- ages;
- locations;
- character behaviour;
- world rules;
- period accuracy;
- chapter handoffs.

### Prose Review

Review both **verbal composition** and **visual composition**.

Verbal:

- sentence rhythm;
- paragraph rhythm;
- imagery;
- dialogue;
- repetition;
- emotional continuity;
- scene-specific voice.

Visual:

- paragraph density;
- whitespace;
- isolated lines;
- dialogue grouping;
- diegetic elements;
- visual weight;
- page geometry.

Do not compose every chapter as a uniform left-anchored wall of prose.

Visual variation must serve the scene rather than follow a mechanical left/centre/right formula.

The renderer may impose alignment limitations; the composition itself must still avoid one-sided visual weight.

# 12. Character Knowledge Control

For each important scene, information belongs to one of four levels:

**Character knows → Character infers → Character does not know → Author/system knows**

Documentation knowledge does not automatically become character knowledge.

For first-person narration:

**Observation ≠ explanation.**

Characters may:

- notice;
- infer;
- misunderstand;
- suspect;
- investigate;
- remain uncertain;
- be wrong.

This is especially important for Jonah/Ira and Kuoh's hidden supernatural ecology.

---

# 13. Scope Control

When a new idea appears, classify it:

**Required now / Required later / Useful but optional / Open question / Proposal / Raw ideation**

If it does not affect the current milestone, defer it.

Do not interrupt a nearly complete phase with unrelated conceptual expansion.

Retired projects remain retired unless explicitly revived.

---

# 14. Definition of Done

A task is complete only when:

- the requested result exists;
- required sources were checked;
- relevant locks were respected;
- no known blocker remains;
- the result was verified;
- important changes were documented;
- the next dependency is clear.

“Written” is not automatically done.

“Implemented” is not automatically done.

“Looks good” is not sufficient verification where objective correctness matters.

---

# 15. Phase Completion Gate

Before closing a phase:

- objective satisfied;
- deliverables present;
- dependencies resolved;
- known defects recorded;
- unresolved questions marked;
- documentation updated;
- next phase identified.

If it cannot safely close:

**keep it open.**

Do not declare completion merely to move forward.

---

# 16. Change Control

When a locked decision changes:

1. identify the old decision;
2. identify the new decision;
3. record why it changed;
4. identify affected documents;
5. identify affected chapters/systems;
6. update authoritative records;
7. verify dependent work.

Do not silently overwrite history.
