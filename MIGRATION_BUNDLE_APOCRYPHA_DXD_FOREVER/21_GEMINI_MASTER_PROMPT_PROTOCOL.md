The failure to prevent is not merely “a prompt was too short.” The failure is a prompt that **sounds complete while carrying a collapsed model**: it lists qualities without explaining how they interact; assumes Gemini can retrieve inaccessible project context; misses temporal handoffs; substitutes a generic editorial audit for chapter-specific creative architecture; or directs prose toward a set of labels rather than a felt reading experience.

The answer is to build the prompt as a **self-contained local model of the novel and the intended reader experience**, not as a bag of instructions.

## 2. Role split: who owns what

### Assistant = master prompter and continuity/research orchestrator

The assistant owns the work upstream of Gemini:
- Recover authoritative source records and the actual manuscript version.
- Reconstruct the exact preceding-chapter handoff and timeline.
- Separate locked author decisions, manuscript evidence, later correction, derived inference, proposal, and UNKNOWN.
- Resolve dependencies, contradictions, prohibited assumptions, and chapter-specific purpose.
- Research the relevant craft questions independently and verify that public sources are accessible.
- Diagnose the actual prose/plot problems before writing the production prompt.
- Translate the recovered canon, craft model, and research into one complete context packet Gemini can use without opening private project records.
- Build the prompt around the chapter's unique narrative problem while carrying forward the established prose-rendering system.
- Audit the finished prompt against continuity, context completeness, source provenance, research usefulness, and output requirements.
- When Gemini returns a revision, compare the result with the prompt, manuscript, canon, and requested outcomes; identify drift or new errors rather than praising surface compliance.

### Gemini = writing and execution model

Gemini receives a complete, chapter-specific production brief and the actual draft being worked on. It should not be expected to recover locked GitHub context independently. It may use public links supplied in the prompt if its environment can access them, but story facts must be included directly in the prompt.

### User = author and authority

The user establishes intended story direction and may lock, correct, or retract decisions. Do not force the user to repeat source recovery, reconstruct chronology, find every defect, or serve as workflow manager. Ask only when a genuinely essential authorial decision cannot be recovered and work cannot safely proceed without it. Do as much independent recovery and bounded work as the evidence permits first.

### Honesty boundary

Never say or imply “I sent Gemini the prompt” unless a connected tool actually sent it and reported success. A prepared prompt and a delivered prompt are different states. If direct messaging is unavailable, say so plainly; do not pretend a paste-ready prompt was transmitted. Still complete all source recovery, research, prompt construction, and audit that can be performed.

## 4. Mandatory work loop before prompt composition

Use the project execution loop:

**ORIENT → TRACE → VERIFY → PLAN → EXECUTE → AUDIT → RECORD → HANDOFF**

### A. ORIENT
Read the current control gate and session handoff. Check this protocol and the current memory bridge. Determine what task was last completed and whether a STOP condition remains active.

### B. TRACE
Locate, read, and compare:
1. the target chapter's active master state/outline;
2. the actual target draft and version identity;
3. the immediately preceding chapter's actual ending or authoritative handoff;
4. current timeline and calendar/season/age/period records where relevant;
5. locked decisions and later corrections;
6. character knowledge and emotional state;
7. relevant worldbuilding/ontology records;
8. applicable prose architecture and research sources;
9. adjacent chapter effects, especially the planned ending-to-next-chapter causal link.

Do not infer that a planning file is the released manuscript, or that a newer file necessarily outranks a source with higher authority. Do not analyze prose features of a manuscript that is not available.

### C. VERIFY
For each significant claim, determine:
- source and exact evidence;
- authority class;
- whether it is current or superseded;
- whether it is author-locked, manuscript-contained, derived, proposed, reconstructed, or unknown;
- who knows it at this point in the story;
- which later decisions depend on it.

Reconstruct the chronology explicitly before drafting. Record the exact beginning state, ending state, elapsed time, and events that may or may not have occurred. Resolve apparent conflicts through source provenance and chronology, not by choosing the most convenient interpretation.

### D. PLAN
Define:
- the requested deliverable;
- the chapter's unique dramatic job;
- the major dependencies;
- the actual draft-specific problems to repair;
- the public research needed;
- conditions that would invalidate or block the prompt;
- what the complete output must contain.

### E. EXECUTE
Conduct the research and write the full master prompt using this protocol.

### F. AUDIT
Review it as if Gemini has never seen the repository or this conversation. A private source link does not count as transferred context. A heading naming a rule does not count as explaining that rule.

### G. RECORD AND HANDOFF
Record material workflow corrections and locked decisions in the appropriate ledger. Update the memory bridge or its pointer when the operating standard changes. Update the session handoff with touched files, evidence, current state, unresolved issues, and the next safe operation. Fetch written records back from GitHub to verify persistence.

## 5. Reconstruct the chapter's narrative job before writing a prompt

Do not let surface events define the chapter by themselves. Determine what the chapter must *do* in the novel.

Create a private working matrix with at least these dimensions:

| Dimension | Questions to resolve |
|---|---|
| Opening state | Where is the protagonist, at what time, after which exact action/line, and in what physical and emotional state? |
| Immediate want | What does the protagonist want in the opening movement? |
| Chapter-specific dramatic job | What new plot, character, world, or relationship state must this chapter produce? |
| Inner movement | What belief, fear, self-limitation, desire, or conflict changes—and what does not change yet? |
| External movement | What does the protagonist actually do? What causes each major transition? |
| Knowledge boundary | What is seen, inferred, guessed, misunderstood, or still unknown? |
| World function | What does the environment reveal through its ordinary operation, friction, social systems, and irregularities? |
| Causality | How does each major scene change the conditions for the next scene? |
| Ending state | What concrete state differs from the opening? What is still unresolved? |
| Next-chapter handoff | Why does the ending create a reason for the next chapter to occur? |
| Exclusions | What must not happen here, even if it is a familiar franchise convention or a tempting plot shortcut? |

This matrix is a diagnostic tool, not a demand that every answer become exposition or a visible numbered outline in the final chapter.

### When two locked layers appear to conflict

Do not silently choose the more convenient one. Determine whether one is:
- the chapter's primary plot engine;
- an emotional/character layer;
- a setting/world layer;
- an escalation/ending condition;
- an obsolete or superseded instruction.

Make them interact where possible. If they cannot be reconciled without altering a locked decision, preserve the conflict, identify the precise collision, and stop only the dependent claim or operation. Do not let a rich character chapter accidentally omit a locked plotline; do not let a plotline flatten the chapter's emotional purpose.

## 6. Required architecture of every chapter-specific Gemini master prompt

This is the default architecture. Expand, combine, or reorder sections only when the target task benefits; do not mechanically copy a template at the cost of chapter-specific clarity.

### 0. File header and governing instructions
Name the project, chapter, document function, and date/version where verified. Tell Gemini this is a complete production brief rather than a generic prompt. Explicitly forbid compressing it into generic advice or replacing the author's prose system with default AI-fiction habits.

### 1. Project identity and non-confusion
Establish the current novel, universe, protagonist/identity, POV, and relevant continuity scope. Explicitly name adjacent projects or prior systems that must not be conflated when that risk is real.

### 2. Governing creative principle
State the highest-level experiential objective. For EverWorlds, the core is that the prose makes the reader experience the event rather than merely telling the reader it occurred. Explain what that requires in physical, cognitive, spatial, sensory, and causal terms.

### 3. Authoritative handoff
Give the exact preceding-chapter ending or the verified state sequence. Identify what has already been learned, done, visited, decided, and emotionally reached. Tell Gemini what must not be repeated as a discovery. If an exact final line is locked, quote it exactly.

### 4. Timeline, geography, age, and period
Specify the correct story-time position, elapsed time, date/season if established, character age, school/calendar status, travel dependencies, and relevant material culture. Do not invent a date or silently preserve a draft's contradicted date. Distinguish timeline certainty from an unresolved calendar value.

### 5. Chapter's distinct purpose and dramatic engine
Define the chapter's core job in the overall novel, what plotline it must advance, and the internal or relational movements that must coexist with it. Define what this chapter is not. Make mandatory plot requirements explicit enough that an adjacent atmospheric or character layer cannot accidentally replace them.

### 6. Layer integration
Explain how plot, character psychology, worldbuilding, social encounters, atmosphere, and environmental information should be experienced together. Give causality patterns, not a forced scene checklist. Each layer should affect attention, choices, consequences, inference, or emotional pressure.

### 7. Protagonist mental model
Describe the protagonist's relevant emotional history, defenses, ambitions, habits, blind spots, humour, cognitive strengths, limits, body experience, and present change. Distinguish a thematic anchor from a literal line of dialogue or interior monologue. Do not turn character notes into an essay to be inserted into the novel.

### 8. POV and epistemic boundaries
Define tense, narrative distance, voice, and what the protagonist can legitimately know at this point. Distinguish:
- directly perceived evidence;
- memory;
- inference;
- guess or hypothesis;
- misunderstanding;
- author-only facts;
- unresolved world mechanics.

Explicitly prevent omniscient exposition leaking through first person. “Observation is not explanation” should be operationalized with examples where relevant.

### 9. World and setting behaviour
Describe how the world functions independently of the protagonist: people pursuing their own goals, social institutions, infrastructure, weather, objects, movement, recurring landmarks, background interactions, and environmental systems. Specify how much should be foregrounded and what must remain peripheral or unknown.

### 10. Prose modes and elasticity
Define the distinct modes this chapter needs and when each applies. For example:
- grounded physical realism for ordinary action, transit, administration, and objects;
- high-resolution perceptual rendering when light, motion, material, sound, spatial relation, or physical response materially shape the scene;
- close cognitive rendering when automatic reactions, appraisals, conscious thoughts, or decisions diverge;
- compression when details add no new orientation, consequence, character, or mood;
- heightened/ominous rendering only when the underlying situation earns it;
- comedy or lyricism only when it arises naturally from voice or experience.

Do not apply one intensity or sentence pattern across every scene.

### 11. Explain every authorial shorthand
If the author uses terms such as “RTX,” “Spark in Zero Physics,” “elastic prose,” “open-world prose,” or similar, define what the shorthand means in practice, what it explicitly does not mean, and how it should change sentences and scene structure. Never assume a label explains itself. Never convert metaphorical design vocabulary into literal in-world physics.

### 12. Perceptual rendering and spatial continuity
Make the physical scene reconstructable. Track bodies, objects, routes, obstructions, distances, entrances/exits, movement, orientation, light, sound sources, material, texture, temperature, friction, weight, inertia, and consequences when relevant.

The reader should be able to keep imagining the scene after a sentence ends. Use spatial cues incrementally. Do not produce an inventory of everything visible; perception is selective and attention is finite. An event need not receive a miniature descriptive essay. The detail should be proportionate to its function.

### 13. Cognitive rendering
Do not translate all cognition into explicit narration. Distinguish, where useful:
- automatic registration;
- involuntary orienting/attention;
- implicit appraisal;
- affect/body response;
- conscious interpretation;
- verbal thought;
- deliberate decision;
- action and later reinterpretation.

A character may act before articulating a theory. Thought should feel like thought; not every perception needs a sentence explaining its meaning. Psychological development should manifest in changed choices and consequences, not just stated insight.

### 14. World response / physical behaviour
The setting should feel active because material things respond to forces and contact. Movement should carry weight, friction, inertia, obstruction, vibration, sound, shifting fabric/hair, heat, reflection, and other relevant consequences. Do not make every sentence sensory-intensive; establish a physically continuous baseline and raise the detail only where the scene calls for it. Do not turn “the world feels alive” into magical behaviour unless the canon supports magic.

### 15. Intensity and contrast control
State how ordinary, detailed, rich, unusual, heightened, and supernatural moments contrast. If every moment is rendered at maximum sensory intensity, no moment stands out. If every object is ominous, unease becomes a verbal label rather than an experience. Intensity must change with scene function and evidence.

### 16. Research-backed diagnostic model
Supply public, accessible sources directly in the prompt. For each source, include author/title/date or venue where verified, stable link/DOI, exact claim it supports, relevant limits, and the prose/plot problem it helps diagnose. Require Gemini to use the source as evidence—not authority to overrule story canon, not a universal law of style, and not a decorative bibliography.

### 17. Actual draft diagnosis
Name the actual scenes, transitions, plot turns, repeated beats, specific continuity violations, and observed prose defects. Quote or identify precise passages only from the actual supplied draft. Separate hard contradictions from craft risks, subjective preferences, and unresolved questions. Never invent a quote to make a diagnosis sound concrete.

### 18. Explicit prohibitions and known failure modes
Include chapter-specific hard constraints plus relevant global safeguards: no generic franchise reconstruction; no unsupported mechanics; no instant character transformation; no author knowledge leakage; no repeating established discoveries; no chronology compression; no decorative adjective inflation; no formulaic fragment strings; no scene replacement simply because a different plot seems easier to write.

### 19. Execution instructions
Ask Gemini to perform the actual requested work on the actual draft. If the user asks for a critique, diagnose the manuscript. If the user asks for a repair, revise it. If both are requested, give a concise evidence-based diagnosis and the complete corrected text. An outline or list of suggestions is not a substitute for a requested full revision.

### 20. Output contract
List exact deliverables, in order, and the format. Define what “complete” means. Require explicit accounting for unresolved canon dependencies, without forcing the novel itself to explain all open questions. Do not ask the user for already-recoverable facts or add generic encouragement/process narration.

### 21. Final self-audit
Require Gemini to check the returned result against timeline, handoff, chapter purpose, canon/unknowns, character change, scene geography, causality, prose elasticity, research scope, and ending-to-next-chapter continuity. This is a final verification step, not a substitute for author judgment.

## 7. Research protocol: evidence must change the diagnosis

Research is not a list of impressive academic links. It must answer a question that affects the actual manuscript.

For each research question:

1. **QUESTION:** Name the concrete craft uncertainty.
2. **SOURCE/METHOD:** Locate a reliable public academic source or credible specialist source. Prefer primary studies/reviews for empirical claims and original craft scholarship for literary concepts.
3. **VERIFICATION:** Confirm title, author, date/venue, DOI/stable URL, and that the linked page supports the claim. Do not cite a paper from a remembered title alone.
4. **MECHANISM:** State what the source actually studies or argues.
5. **OBSERVABLE EFFECT:** State what would be visible in reading or in the manuscript if the proposed mechanism matters.
6. **LIMITATIONS:** Include method/sample/context limits; a laboratory reading result does not automatically prescribe an artistic rule.
7. **PROSE TRANSLATION:** Explain how the mechanism affects a specific type of scene, sentence, transition, inference, or structural choice in this chapter.
8. **IMPLEMENTATION RULE:** State a concrete change that follows, and the cases in which it should not be applied.
9. **FAILURE CONDITION:** Explain how the rule could be overused, misapplied, or contradicted by the draft's actual needs.
10. **VERIFICATION TEST:** Identify a passage-level or structure-level comparison that could reveal whether the revision improves the intended effect.
11. **DEPENDENCIES:** Note which prompt sections or manuscript decisions are affected.

Do not overfit fiction to empirical findings. A source may help explain perception, attention, immersion, spatial representation, memory, or narrative viewpoint; it cannot prove that a particular sentence, trope, or style will universally work. Preserve the distinction between empirical evidence, scholarly interpretation, author-defined design principles, and editorial judgment.

### Public accessibility
The final prompt must contain research links that Gemini can plausibly open publicly. It must not rely on a locked GitHub file or a repository URL as a substitute for supplying the relevant project information. If a public source is paywalled, provide the best legitimate accessible abstract/author version or choose an accessible alternative; accurately state any access limitations.

## 8. Context-transfer protocol: Gemini must not have to guess

Anything required for correct execution must be stated in the prompt or included in material supplied directly to Gemini.

For every context item, ask: “Would Gemini get this right if it could not open the project repository, cannot see the prior conversation outside the provided prompt, and does not know which draft is authoritative?”

If not, embed the relevant information.

The prompt must supply:
- exact project identity and relevant terminology;
- verified starting point and preceding chapter ending;
- current timeline plus explicit unresolved date fields;
- chapter-specific dramatic purpose;
- locked decisions and prohibited changes;
- age and other applicable boundaries;
- protagonist state and knowledge boundaries;
- necessary setting/world mechanics;
- distinction between canon and unknowns;
- actual draft-specific defects;
- research sources with what they support;
- exact deliverable and required audit.

Do not paste the entire repository indiscriminately. Context transfer is not a lore dump. Select and explain the *specific relevant facts* Gemini needs to make the right decisions; preserve enough detail and relationships that the model does not have to reconstruct the system from one-dimensional labels.

### Facts versus interpretation

Use explicit language such as:
- **LOCKED FACT / AUTHOR DECISION**
- **MANUSCRIPT EVIDENCE**
- **DERIVED CONCLUSION**
- **PROVISIONAL CRAFT HYPOTHESIS**
- **UNKNOWN / DO NOT INVENT**

The labels must influence the instructions. For example, “UNKNOWN” should prevent Gemini from naming a mechanism or making it drive plot logic; it is not enough to list an unknown in a footer and then rely on it in the main outline.

## 9. Prose quality: test the experience, not style labels

The production brief must preserve the following distinction.

### Experiential rendering
The prose should create the conditions for the reader to experience the event. The reader should be able to track what the protagonist's body is doing, how the space constrains movement, what attracts or interrupts attention, which causes produce which effects, and how sensory details change the reader's understanding of the situation.

### Not a sensory inventory
“More detail” is not the goal. A description fails if it stalls the action, repeats known information, breaks spatial flow, overloads the paragraph, advertises its own beauty, or supplies atmosphere that the scene has not earned.

### Not constant cinematic intensity
High perceptual resolution is one available mode. It is not the baseline intensity for every sentence. Use detail to orient, focus, alter the situation model, reveal character, establish independent world activity, create contrast, or support a specific emotional/narrative function.

### Elastic prose
Sentence cadence, paragraph density, narrative distance, explicit thought, description, dialogue, silence, and compression should respond to the current scene's task. Do not force identical paragraph shapes or sentence fragments onto walking, reflection, banter, action, fear, and revelation.

### Character-coloured perception
The same place should not be narrated identically by every protagonist. Ira's attention is influenced by his current goal, body, memory, defensive habits, uncertainty, humour, attraction when age-appropriate, fatigue, and learned social expectations. The narrator must not automatically know which interpretation is correct.

### Spatial integrity
Maintain a working geography. Movement should have a cause, a path, and a consequence. Do not teleport people between descriptive beats, refer to objects before their location is established, or make the environment reset for each paragraph.

### Independent world
Other people and background systems should continue to exist when Ira is not directly interacting with them. Convey this selectively through concurrent activity and environmental traces, not through a huge catalogue of unrelated pedestrians.

### Causal continuity
For major scene changes, know what action/observation/inference caused the next choice. Avoid chains of “I saw X; I thought Y; then I saw Z” when no meaningful event or decision connects them. Reflection belongs in the flow of experience, not as an essay stapled between objects.

## 10. Draft diagnosis: standards of proof

Every concrete criticism of the actual chapter must satisfy at least one of these:
- demonstrable continuity/timeline conflict with a verified source;
- POV or knowledge violation;
- contradiction with a locked chapter purpose or plot requirement;
- missing causal transition that makes an event unearned or arbitrary;
- spatial ambiguity that prevents reconstruction of action;
- repeated or redundant information;
- prose rhythm/density causing a defined delivery failure;
- explanatory narration that duplicates or contradicts what the scene already conveys;
- a worldbuilding claim that exceeds known canon;
- a scene that consumes space without changing action, inference, character, world understanding, tension, or next-scene conditions;
- an ending that does not establish the intended next-chapter question/pressure.

Label other recommendations correctly as craft hypotheses, taste judgments, or alternatives. Do not overstate a stylistic preference as an objective defect.

Before recommending deletion or replacement, identify the function the scene currently serves and whether that function can be retained in a better form. Preserve useful material where possible, but do not preserve a scene at the cost of a locked plot obligation.

## 11. Output contract and acceptance gates

A prompt is not ready until every applicable gate passes.

### Gate A — Source identity
- Is the actual target manuscript present and is its identity/version known?
- Are the controlling master state and preceding handoff recovered?
- Are important quotations exact?

**Fail:** STOP the manuscript-specific claim if the required text cannot be recovered. Do not invent passage-level defects.

### Gate B — Chronology
- Does the opening begin at the correct time and physical/emotional state?
- Are elapsed time, date, season, age, and next-event dependencies consistent?
- Are unresolved dates left unresolved rather than filled in?

**Fail:** Do not ship a prompt containing an unaddressed conflict.

### Gate C — Chapter purpose
- Is the chapter's actual plot function unmistakable?
- Are major character/environment layers integrated rather than substituted for the plot?
- Are exclusions explicit?

**Fail:** Rewrite the brief; a beautiful atmosphere plan cannot compensate for an omitted locked plotline.

### Gate D — Context self-containment
- Could Gemini execute without opening private project files?
- Does the prompt explain shorthand rather than merely naming it?
- Are all necessary canon and constraints stated directly?

**Fail:** Add the missing context.

### Gate E — Research
- Are links public/access-checked where possible?
- Is every citation tied to a craft question and concrete manuscript defect?
- Are limits and alternative interpretations included?
- Is empirical evidence distinguished from editorial inference?

**Fail:** Verify or replace the source; do not pad with unrelated references.

### Gate F — Creative method
- Does the prompt make the experiential target operational?
- Does it describe the relevant interaction of physical action, attention, space, cognition, voice, world, and plot?
- Does it use elastic modes and contrast rather than applying one adjective-heavy style everywhere?
- Does it define failure modes clearly enough for Gemini to avoid them?

**Fail:** Add causal and scene-level explanation, not more unexplained labels.

### Gate G — Execution
- Does Gemini have the actual draft or a clear statement of which supplied draft to edit?
- Is the requested operation explicit?
- Does the output contract require the actual deliverable, not merely advice?

**Fail:** The prompt is an audit plan, not yet a production prompt.

### Gate H — Final authoring integrity
- Does the output preserve author intent?
- Does it avoid invented canon and future knowledge leakage?
- Does it make uncertainty visible?
- Does it preserve the correct next-chapter handoff?
- Is any claimed direct send verified by an actual tool result?

**Fail:** Correct the prompt or state the exact unresolved blocker.

## 12. Known failure pattern to prevent

The recent Chapter 8 prompting attempt failed because it was too much like an editorial audit and did not sufficiently recreate the Chapter 6 prompt's operating model. It listed requirements but did not give Gemini enough integrated creative architecture. It also risked making a self-contained-sounding prompt depend on private project knowledge and failed to cleanly reconcile Chapter 8's character/exploration requirements with its locked Power plotline.

Therefore future work must not:
- confuse “long” with “complete”;
- confuse detailed lists with an operational model;
- give Gemini links to inaccessible project facts instead of embedding them;
- let the chapter's secondary atmosphere or emotional layer replace the primary dramatic job;
- carry one chapter's plot architecture into another because the prompt method is reusable;
- cite research without explaining the mechanism and limitation;
- diagnose an unseen draft using reconstructed quotations;
- deliver a prompt full of warnings but no actual instructions for scenes and causal development;
- stop after producing the prompt when the user actually requested a complete revision and the available workflow supports more;
- claim delivery when only drafting has occurred.

A correct prompt is one Gemini can use to make good decisions without guessing—not one that merely contains many paragraphs.
